# sepal.nvim

- Tests: `nvim -l tests/run.lua` from the repo root (uses a fake agent, no Claude Code needed). `SEPAL_TEST=<part of a test name> nvim -l tests/run.lua` runs just those while iterating. `SEPAL_DEMO_CHECK=1 nvim --headless -u tests/demo.lua` runs the swarm demo end to end (`nvim -u tests/demo.lua` to try it by hand).
- Modules: lua/sepal/init.lua (config, `setup()`, colors, `notify`/`progress`, `status()`, the task draft: picker, keys, `task_sharpen`, `skills`, check detection), agent.lua (a task's life: snapshot, worktree, `prepare`, the agent in a hidden terminal and its hooks, check/retries, land/undo, reply/continue/stop, swarm, review tab, chats), git.lua, inbox.lua (the per-repo JSON store and the oil-like inbox buffer), panel.lua (the read-only board and context bar), health.lua (`:checkhealth sepal`), plugin/sepal.lua (`:Sepal` and its subcommands).
- Kinds are `implement`/`btw`/`guide`/`orchestrate` in code (a `guide` is a read-only btw whose notes are the guideme skill), saved inboxes and the `models` keys; the UI calls them feat (`f`), btw (`b`), guide (`g`) and swarm (`s`). Only `claude…` and `devin…` executables are supported agents (`agent.kind`).
- Statuses (inbox `STATUS`): queued, running, checking, ready, landed, nochange, failed (check failed), error (failed), needs, stopped, interrupted, undone, answered (btw), planned and swarmed (orchestrate). Adding one means the inbox, the panel's `HINT`/`COUNTS`, `inbox.counts` (statusline), `:Sepal land`/`clean` lists and the docs.
- Keep git work off the main loop where callers allow it (local `bg`, exported `commit_bg`, `stat_bg`, `update_refs_bg`, `plan_bg`, `delete_refs_bg`, `status_bg` in lua/sepal/git.lua); batch git processes (`files`, `delete_refs_bg` with a list) instead of one per file/task.
- Landing/undo plan via `git.plan_bg`, which rechecks each file before applying; `agent._t.landing` lists the in-flight ones and tests wait on it (`settled()`/`idle()`).
- Optional plugins (fidget, fff) go through `optional(name)` in lua/sepal/init.lua (a missing module isn't searched for again until 'runtimepath' changes); the open task draft is `require("sepal").draft()`, don't scan buffers for `vim.b.sepal_task`.
- Inbox saves/renders inside `inbox.batch(fn)` are deferred until the outermost batch ends (one save per affected repo, one render, also on error); use it for bulk changes.
- A user-facing change updates README.md and doc/sepal.txt together (keys, options and their defaults, statuses, commands).
