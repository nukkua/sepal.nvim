*sepal.txt*  Delegate, verify, land: tasks for Claude Code

==============================================================================
1. INTRODUCTION                                                        *sepal*

You write a task next to your code; Claude Code works on it in a git worktree
(your files never change under you); sepal runs the task's check itself; if
it passes, the result lands in your work tree as unstaged changes, to review
with the git tools you already use. You hear about it when it's landed or
when something needs you. |:Sepal-inbox| lists every task.

Requirements: Neovim 0.12+, Claude Code, git. Optional: fff.nvim to pick
files, fidget.nvim for a spinner.

==============================================================================
2. TUTORIAL                                                   *sepal-tutorial*

1. Map two keys:
>lua
   vim.keymap.set({ "n", "x" }, "<leader>as", ":Sepal task<cr>")
   vim.keymap.set("n", "<leader>ai", "<cmd>Sepal inbox<cr>")
<
2. Select the code you mean (or don't) and press <leader>as. Fill in the
   task. "Done when:" is a shell command that has to pass, e.g. `make test`.
3. <c-c><c-c> sends it. Keep working; more tasks run in parallel.
4. "✓ landed: …" means it passed the check and is in your files, unstaged.
   The "·" lines under it are the decisions the agent made alone: read them.
5. Review with `git diff`, gitsigns, fugitive. |:Sepal-undo| takes it back.
6. A warning means it needs you: <leader>ai shows why; `r` replies to the
   agent, `L` lands anyway, `o` opens its chat.
7. To watch the agent while it works: |:Sepal-open| (or `o` in the inbox).

==============================================================================
3. SETUP                                                         *sepal-setup*

`setup()` is optional. These are the defaults:
>lua
  require("sepal").setup({
    cmd = { "claude" },
    args = { "--permission-mode", "acceptEdits" },
    check = nil,
    retries = 1,
    land = "auto",
    prepare = nil,
    worktrees = vim.fn.stdpath("state") .. "/sepal",
    task_suggest = nil,
    max_running = 2,
  })
<
`cmd`        the agent: Claude Code. A task runs `cmd <args> <task>` in a
             hidden terminal in its worktree; hooks passed with --settings
             tell sepal what it does and when its turn is over.
                                                                *sepal-args*
`args`       added to each run. The task's check is always allowed. When the
             agent asks for permission it waits for you: sepal warns
             ("▲ …: Claude needs your permission to use Bash · :Sepal open")
             and you answer in |:Sepal-open|. Allow what you trust upfront:
             `{ "--permission-mode", "acceptEdits", "--allowedTools",
             "Bash(npm run lint)" }`. Other flags too: `"--model", "opus"`.
`check`      the check for tasks without a "Done when:" line, e.g.
             "make test". nil: those tasks aren't checked.
`retries`    when the check fails, the agent gets its output and this many
             more tries.
`land`       "auto": a task that passes lands by itself, when it lands
             cleanly. "manual": it waits in the inbox for `L`.
`prepare`    shell command run in each new worktree before the agent, to
             bring in what git doesn't have: `ln -s "$SEPAL_ROOT/node_modules"
             node_modules`. $SEPAL_ROOT is your repo. What it makes isn't
             counted as the agent's work.
`worktrees`  where the worktrees and each repo's inbox (JSON) live.
                                                        *sepal-max_running*
`max_running` tasks running at once; the rest wait in the inbox as
             "queued" and start when one is done. nil: no limit. Each
             running task is a Claude Code process.
                                                       *sepal-task_suggest*
`task_suggest` argv that gets the task buffer on stdin (your idea and
             Files:) and prints the finished task. <c-c><c-s> runs it. For
             Claude Code, pass -p and --no-session-persistence.

==============================================================================
4. COMMANDS                                                    *sepal-commands*

                                                                      *:Sepal*
:[range]Sepal [task]
                  Write a task in a buffer above the code: Scope, Goal,
                  Constraints, Done when, Files. In it:
                    <c-c><c-c>  send it and close the buffer
                    <c-c><c-s>  have |sepal-task_suggest| write the task
                    <c-c><c-f>  add a file under Files: as @path
                    <c-c><c-k>  discard the task
                  With a [range], those lines go in as a "Selection:
                  path:10-20" code block. Closing the window drops the
                  draft: :Sepal task always starts a new one. Outside a
                  git repo the task stays in its buffer.
                                                               *:Sepal-inbox*
:Sepal inbox      Every task of this repo, newest first, with what to read
                  under each (assumptions, why it needs you, the failing
                  check's output). In it:
                    <CR>  everything the task changed, as a diff (q closes)
                    L     land it (with conflict markers if it overlaps
                          your edits)
                    u     take a landed task back out
                    r     reply: the agent continues in the same chat from
                          what it did; it's checked and lands again (only
                          what's new)
                    o     watch it (running) or open its chat (done)
                    x     stop it
                    D     drop it
                    q     close the inbox
:Sepal land       Land the newest task that's waiting.
                                                                *:Sepal-undo*
:Sepal undo       Take the newest landed task back out (a merge too: your
                  edits since stay).
                                                                *:Sepal-open*
:Sepal open       The newest task in Claude Code, full screen. While it
                  runs: the agent at work, live; type to it if you like.
                  `q` (normal mode) hides it, it keeps going. Once it's done:
                  its chat (`claude --resume`). From the agent or a chat
                  (normal mode) it's a toggle: it leaves, like `q`.
:Sepal stop       Stop every running task.
:Sepal clean      Drop the tasks that are over: landed, no changes, undone,
                  stopped, interrupted.

Lua: `require("sepal").task()`, `.inbox()`, `.land()`, `.undo()`, `.open()`,
`.stop()`, `.clean()`.

==============================================================================
5. HOW IT WORKS                                                 *sepal-landing*

Your work tree (uncommitted and untracked files too) is saved as a commit
through a temporary index; your index and branches aren't touched. The agent
works in a worktree of it, then sepal runs the check there. Landing applies
the change to your work tree with a three-way merge per file (git
merge-file), unstaged. With land = "auto" it only lands when that's clean: no
overlap with your edits and no unsaved buffer of a file it touches; otherwise
the task waits as "needs you". Results are kept as refs/sepal/<id>/* until
the task is dropped. A task running when Neovim quits shows as "interrupted";
`r` continues it.

Claude Code may ask to trust a task's new worktree before it starts. sepal
warns ("▲ …: Claude Code asks to trust the worktree · :Sepal open"); answer
it there.
